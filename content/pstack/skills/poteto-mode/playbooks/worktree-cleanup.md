### Worktree cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

1. Snapshot and audit. Record `df -h /`, then run `node <poteto-mode-skill-dir>/scripts/worktree-audit.mjs <repo-path>` (principle-build-the-lever). Resolve the script against this skill, not the target repository. Native Pi shell tools supply `PI_SESSION_FILE` for the exact current transcript when one exists. When Pi's working directory belongs to the workspace being cleaned and that transcript is available, construct `{cwd,directory}` from the working directory and the transcript's containing directory. Pass this JSON as one shell-quoted `--history-scope` argument. Add other scopes only when the user explicitly authorizes them; a current transcript outside the target repository does not authorize its siblings. If the transcript is unavailable, omit the scope and report the history gap instead of guessing a directory. The audit reads paths from `git worktree list`, never hand-typed: worktrees can live outside the usual repository directory (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest matching stored Pi session, then suggests a bucket. It refreshes `origin/main` and reads your GitHub PRs: non-deleting, not read-only. Background the audit if it is slow, but do not assign it to a read-only subagent. Report its evidence gaps, not just the table.
2. The bucket is advice, not permission. The pinned and active sessions are the real artifact (principle-prove-it-works). Get that set from the user or an available host interface and cross-check every candidate. A `safe` worktree can still be pinned, so the pinned set wins. Pi labels and stored session files are not a complete roster of pinned or live sessions. Missing stored history is not evidence of inactivity, and the last-chat time is a file-mtime heuristic.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the admitted session evidence and report whether the work is ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). Use the audit's session paths and IDs; read typed Pi message entries across branches, without dumping whole transcripts. Follow the [Recall access boundary](../../recall/SKILL.md#pi-transcript-access): do not scan the global history root or follow `parentSession` into another project. A live or pinned session can spawn arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never appear in a host sidebar. Reconcile transcript evidence with the pinned/active set rather than inferring pins from transcript text.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause. A non-open PR, including CLOSED and unmerged, can make a worktree eligible under the original abandoned-work rule; it does not override these usage and loss gates.
5. Prune the confirmed set. Recheck each target's identity and ownership, then `git worktree remove --force <path>`. If the directory survives on ignored build artifacts, inspect what remains and verify that exact path still belongs to the confirmed target before `rm -rf` of that path, then `git worktree prune`. Keep branch refs; this workflow removes worktrees, not branches. Confirm with `df -h /` and re-list. Do not extend the cleanup to simulators, host application state, or unrelated caches.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, evidence gaps, and a one-line reason for each held back (in-use by which session, or uncommitted work).
